## 2. Scale inputs for 2.11.6 (do not implement yet)

### 2.1 Global scans that run every tick (ungated)

N = entities, H = households.

- `snap_infants_to_caregivers` 3×/tick (`pipeline.rs:157,190,265` → `dependents.rs:12-31`, builds a `HashMap` N each time).
- `reassign_orphaned_dependents` (`dependents.rs:68-82`, `HashSet` N + collect N) even when `deaths` is empty.
- `process_witnessed_deaths` (`grief.rs:30-88`, per-survivor `Vec`) even when nobody died.
- `synchronize_dependent_memberships` (`households.rs:526-557`, two `HashMap` N) + `household_sync_scans += N+H` (`pipeline.rs:257-260`).
- `settle_completed_migrations` (`households.rs:197-239`) + `dissolve_empty_households` (`households.rs:459-480`) + `settle_basic_inheritances` (`households.rs:336-445`, builds `living: HashSet` N every tick even with no dissolutions).
- `process_due_pregnancies` (`lifecycle.rs:220-251`, `occupied: HashSet` N + scan of all mothers every tick).
- `process_social_interactions` (`autonomy/social.rs:469-636`, `id_to_index: HashMap` N rebuilt every tick).

### 2.2 Per-entity-per-tick multipliers

- `scan_visible_resources` ~169 tiles/entity/tick (`autonomy/perception.rs:214-215`, r=6).
- `remembered_food_targets` builds a `Vec` + `BinaryHeap` O(Kr) **per entity per tick** (`autonomy/mind.rs:643-668`, called from `autonomy/mod.rs:258` even for satiated entities).
- `reconcile_resource_memory`, `perceive_entities` (spatial + sort), path alloc per successful A* (`pathfinding.rs:317-333`), `Vec::insert` memmoves in `perception.rs:52-63,118-132`.
- `population.iter().find/filter` O(N) lookups still exist in `decision.rs:564,632-653` and `action.rs:190,215,381,459`, while other call sites already use `binary_search_by_key` (population is sorted by id — use it everywhere).
- No per-tick budgets exist: `DEFAULT_MAX_ITERATIONS = 50_000` (`pathfinding.rs:6`) is per-search, and there is no cap on searches/tick or nodes/tick.

### 2.3 New data point: perf #216 changed the social hotspot (main `4dad87c`)

`partnerships::try_form` ran `relationship_between` (multiple BFS traversals +
heap allocs) on every social interaction (~4.3k/tick in `lineage-1000`,
~23 µs/call, 91.9% rejected later by `interaction_count < 3`). Fix: cheap
guards (health, existing partner, adult stage, known-entity, count ≥ 3,
affinity) now run before any kinship traversal; `kinship.rs` also early-exits
on empty genealogy and reuses `first_ancestors`. Result (`lineage-1000`):
`social_interactions_us` 114.7 ms → 8.4 ms/tick (−92.7%), tick total −45.3%,
controls `dense-social-1000` −38.5% / `baseline-10000` −23.7% total, behavior
identical (26 work/state counters byte-identical). Lesson for the scheduler:
guard-ordering inside hot paths beats structural rewrites; keep measuring the
social funnel per scenario before sharding it.

### 2.4 Candidate directions (only after 2.11.7 hash lands on main)

- **Event-driven:** gate orphan/grief/partner-cleanup on `!deaths.is_empty()`; gate household settle/dissolve/inherit on `membership_changed || !deaths.is_empty()`; skip encounter/conflict sort+dedup on empty vecs (`mod.rs:1013,1381`); replace pregnancy scan with a `BTreeMap<due_tick, Vec<id>>` queue.
- **Fuse/shard:** fuse the 3× infant snap into 1× reusing `caregiver_index` instead of rebuilding a `HashMap`; fuse advance/starvation/collect/retain/index-rebuild into fewer passes; shard daily work (`relationship_decay`, `try_conceptions`, `plan_daily_migrations`) by `id % 24 == tick % 24` to avoid the daily spike.
- **Budget:** add `max_searches_per_tick` + `max_nodes_per_tick` (counters already exist), defer `Explore/Socialize` when over budget, prioritize `Eat/Protect`; only run `remembered_food_targets` when `hunger >= FOOD_SEARCH_THRESHOLD` (`config.rs:7`).

### 3.1 What the branch already fixed (do not re-do)

- `known_chunks: HashSet → BTreeSet` (`autonomy/mind.rs:199`) — the only
  persistent hash-set is now canonically ordered.
- Social hot path `id_to_index: HashMap` removed → `binary_search_by_key`
  (`autonomy/social.rs:474-496`).
- `snap_infants` no longer builds `HashMap` N 3×/tick → infant-filtered
  `Vec` of updates via `binary_search` (`dependents.rs:6-33`); orphan
  reassignment `alive: HashSet` removed → `binary_search(...).is_err()`
  (`dependents.rs:71-88`).
- Household planning/settling/stats `HashMap → BTreeMap` (`households.rs:115,
  233,241,282`); `synchronize_dependent_memberships` map removed →
  `binary_search` + health check (`households.rs:558-580`).
- Grief `dead_by_id: HashMap` removed + `if deaths.is_empty() { return; }`
  (`grief.rs:29-46`); linear `find` over `deaths` slice is fine (D is tiny,
  empty ticks now free).
- Spawn-candidate tie-break added: `(manhattan, y*width+x)` in both food and
  fallback sorts (`lifecycle.rs:350,393`) — exactly the canonical-order fix
  this playbook asked for.
- `write_f32` normalizes NaN → `0x7fc0_0000` and `±0.0` → `0`
  (`state_hash.rs:70-79`) — better than the first proposal.

### 3.2 Gaps before 2.11.7 can be marked done

1. **Event hash is partial.** `events.rs:260-284` hashes
   `id/tick/actor/target/location/kind` but drops `caused_by`, `related_ids`,
   `cause`, `details`. Two runs with identical kinds but different causal
   chains hash equal. Decide: either hash the full envelope or document the
   exclusion as intentional (causality-only debug) — do not leave it silent.
2. **World hash is resources-only.** `state_hash.rs:127-133` covers live
   deposits (index/kind/amount) but not `tiles[].terrain`, `renewable[]`,
   `region_ids`. A terrain-generation divergence after init would hash equal
   (resources would likely still diverge downstream, but indirectly). Add at
   least `terrain as u8` per tile or state the assumption.
3. **`paused` excluded.** Scalars hashed are tick/seed/ids/counters
   (`state_hash.rs:117-124`) but not `paused`. Correct for evolution, but
   snapshot load (2.11.8) must still persist it — note the split.
4. **Single golden.** One pin (10 pop / 100 ticks / tiny arena) guards
   regressions but not scale paths (households, lineages, 1k/10k). Add at
   least a `lineage-1000`-flavored golden and a households golden before
   calling 2.11.7 done.
5. **Missing parities:** debug-vs-release logical equality and replay-from-
   checkpoint are still open (checkpoint needs 2.11.8). Add the debug/release
   hash comparison now; schedule replay with persistence.
6. **Hygiene:** `pub mod state_hash` exposes `StateHasher` internals wider
   than needed (A11 tail); narrow to `pub(crate)` once the bridge only needs
   `SimulationStateHash`. Consider the CI guard `rg
   "rand::|thread_rng|getrandom::|SystemTime::now" engine/src` proposed
   earlier — still not present.

## 3.3 Original audit (pre-branch reference)

Good news, verified by reading the code:

- No `rand`, `thread_rng`, `getrandom`, `SystemTime`, `rayon`/`par_iter` in simulation logic. All randomness is `mix64(seed, id, salt, tick)` in `lifecycle.rs:294-312` and `resources.rs:5-12`.
- All `Instant::now` uses are behind `Option<Profile>` (`autonomy/mod.rs`, `simulation/mod.rs:744,862,946`, `pipeline.rs:56,95,302`). Production path (`run_step`) never touches the clock. Parity tests already assert step == profiled step.
- `entities` and `households` are append-only `Vec`s sorted by id (`mod.rs:696-732`, `households.rs:626-634`); `retain` preserves order. `binary_search_by_key` is therefore valid everywhere.
- `BTreeMap` was already chosen where iteration matters (`genealogy.rs:19-20`, `mod.rs:321-334` for `caregiver_index`), with explicit comments.

Residual risks to fix as part of the hash work:

1. ~22 `HashMap`/`HashSet` (std, `RandomState`) remain (`dependents.rs:13,69`, `households.rs:84,202,210,344-345,464,530`, `grief.rs:36`, `social.rs:475`, `lifecycle.rs:226`, `mind.rs:199` persistent `known_chunks`). None is *iterated* to mutate state today (only `get/contains/entry/len`), but any future `for (k,v) in map` would be nondeterministic. Hottest: `social.rs:475` (rebuilt every tick — replace with `binary_search`).
2. `known_chunks: HashSet<u32>` (`mind.rs:199`) is the only persistent hash-set in state — sort before hashing, consider `BTreeSet`.
3. Float tie-breaks: `decision.rs:471-474` picks max utility with `max_by(total_cmp)` and no explicit goal tie-break; `lifecycle.rs:350,388` sorts spawn candidates by distance only (`sort_unstable`). Add total tie-breaks (`(dist, index)`, goal discriminant) before freezing golden hashes.
4. World `f64` fields (`altitude/moisture/temperature`) should not be hashed raw if the hash must hold across wasm/native — hash `Terrain as u8`, quantize or exclude the floats.

### `SimulationStateHash` proposal

- Hasher: fixed chain reusing existing `mix64` (`h = mix64(h ^ piece)`), never `std` `DefaultHasher`.
- **Include, in fixed order:** `seed, tick, next_entity_id, next_household_id, births, deaths, food_consumed, world_revision`; per entity in id order (pos, sex, lifespan, `hunger/health.to_bits()`, age, path+index, activity, pregnancy, postpartum, movement credit bits, mother/father/caregiver/partner/household, personality bits, inventory, action_tick, mind: goal/plan/goal_since/visible/grief/memory with `known_chunks` sorted); per household in id order; `genealogy.records` in order (exclude derived `children` index or iterate its `BTreeMap` canonically); world `resources`/`renewable` per tile index + `terrain as u8`.
- **Exclude:** `population_cache`, `caregiver_index`, `spatial_grid`, `pathfinding_workspace` (derived/scratch + `Cell` counters), `paused` (UI control), `recent_events` content (bounded eviction — keep a separate event hash if needed), all `*_us/*_ns` profiles, `WorkCounters`, `StateGauges`, `UtilityScores`/explanations (overwritten each tick).
- Tests: same-seed-same-hash across runs; full-run vs chunked-run hash equality; profiled-on/off hash equality; debug/release logical equality; `debug_assert!(ids sorted)` before hashing.

## 4. Persistence inputs for 2.11.8

### Persist YES

- `Simulation`: `tick, paused, entities (Vec, id-ordered), next_entity_id, seed, births, deaths, food_consumed, world_revision, genealogy, households, next_household_id, recent_events` (`mod.rs:316-347`).
- `Entity` (`entity.rs:62-87`): all fields including `path/path_index`, `pregnancy`, `postpartum_until_tick`, `movement_credit`, `mother/father/caregiver/partner/household`, `personality`, `inventory {capacity, amounts:[u16;4]}`, `action_tick`.
- `Mind/Memory` (`mind.rs:517-528,196-204`): `perception_radius, current_goal/plan/plan_index, goal_since_tick, visible_entities (sorted), grief (sorted)`; all of `Memory` (`known_resources, known_chunks (serialize sorted), failed_exploration, known_entities (id-ordered), known_dead (ordered), conflict_history (ordered)`).
- `Household` (`households.rs:18-44`): identity, ticks, migration, inheritance, residence, storage. Membership itself is derived from `Entity.household_id` via `members_of`.
- `Genealogy.records` (append-only, includes the dead). `children` index is rebuildable — persist `records` only in v2, or both + assert in v1.
- `Events`: `VecDeque` content in id order + `capacity` + `next_id` + `total_created` (`events.rs:192-198`).
- World mutable layer: `width/height, tiles[].terrain (+ optionally quantized climate), resources[] per index, renewable[]`.

### Persist NO (rebuild always)

`population_cache`, `caregiver_index`, `SpatialGrid` (has `Cell` counters), `PathfindingWorkspace`, all profiling/counters/gauges. `Kinship` has no state (pure queries).

### Gaps to close for a v1 snapshot

1. Nothing persistent is `serde` today — only world value types (`world.rs`), counters/gauges, and bridge DTOs are `Serialize`. Prefer versioned `SnapshotV1_*` DTOs over deriving on internals (keeps `HashSet`/`VecDeque`/`BTreeMap`/`f32` out of the format).
2. `Grid` does not store its own `seed`/`sea_level` (`generation.rs:4`, `lib.rs:91-99` drop them) — add to header: `format: "nexus-snapshot/v1"`, engine phase, sim `seed`, world seed + dims + sea level, `tick`, checksum.
3. Normalize on write: sort entities/households/records/memories, `HashSet→sorted Vec`, `VecDeque→Vec` in id order; preserve `Inventory.capacity` and `RecentEventHistory.capacity/next/total`.
4. Load order + validation: header/checksum → `Grid` (len, indices, walkability) → re-`detect_regions` and compare → simulation scalars (`next > max(id)`, tick ≥ all referenced ticks) → entities (bounds, `health>0`, `path_index ≤ len`, partner symmetry, caregiver/household/parents exist, pregnancy `due > tick`, affinity ranges, grief `ends > tick`) → genealogy (`children == rebuild(records)`) → households (ordered, residence walkable, dissolved ≥ formed) → events (len ≤ capacity, ids increasing and `< next_id`, ticks ≤ snapshot tick) → **always** rebuild index/grid/workspace, zero profiling.

Bridge DTOs (`bridge/*.rs`) are lossy projections (counts instead of contents, labels instead of enums) — do not reuse them as the snapshot format.
